本文件记录用户针对 APMCM 2026 的明确撰稿要求。后续撰稿、整合与审稿必须读取；当前阶段安排优先于 skill 通用示例。规则依据为本项目用户指令，不将另一赛事的形式当作 APMCM 官方要求。

## 1. 官方模板保真

- 直接使用 `00_赛题与规则/官方发布/2026论文规范与模板/APMCM LaTeX 模板/`。被删除的自建模板不得恢复。
- 官方已有字体、字号、页边距、标题与目录样式、行距、caption 样式均不改。数维杯只借鉴内容层级、叙事与图文组织。
- 官方示例实际采用 XeLaTeX / Times New Roman 分支；沿用该分支，不用 pdfLaTeX 的 newtx 分支替换视觉形式。实测正文 10.5 pt；与早期 11/12 pt 通用要求的差异留在内部验收记录，最终格式检查另行处理，不擅改字体。
- 题号 D，队号 apmcm26301618；此前用户指定页眉文字 `Team Dapmcm26301618 Page X of 25`，保留官方左右位置和字体。页数最终整合时统一核定。
- 初稿阶段不按 25 页压缩论证，不通过缩字号、改边距压页。最终提交仍须检查当届官方页数要求。

## 2. 全文结构与阶段范围

- 全文前置为 Introduction（Problem background / Problem restatement）、Problem Analysis、Model Assumptions and Notation。它们服务整篇论文，不能写成只针对第一问的独立前言。
- 背景可以写全局，问题重述简明分点；问题分析按最新要求，每问写一个简短连贯段落，不分点、不拆段。本轮只填写 P1，P2/P3 留空。
- 全篇核心假设约六条；P1 至多 2–3 条，每条有依据和适用范围，不列无关免责条款。
- 符号表小而必要；后文符号首次出现仍须解释含义、单位和索引。符号表不替代正文定义。
- 章名使用 Problem 1 / Problem 2 / Problem 3，不用 Model I / Model II / Model III。
- 每问主线：数据分析与处理 → 模型建立 → 模型求解 → 结果与充分检验 → Direct answer to Problem N。求解必须明确算法、实际求解器及必要参数。
- Direct answer 简明分点，直接点名模型及模型类型、给出具体结果和输出，不能用泛化的“Model / Results / Output”解释代替答案；保留必要适用边界。
- Model Evaluation 待全部问题完成后再写，届时分 Strengths、Weaknesses、Model promotion，优缺点分点简明。当前只保留空框架。
- Summary、Conclusion、AI 使用披露和 AI 参考文献条目均待全文整合，本轮不填写；这不是取消最终披露要求。

## 3. 图表、公式与数学论证

- 正文图放正文，补充图放附录 B。每张图表必须在段落中先点名引出并说明用途，再出现；图文保持同页或紧邻页，图题与图同页。
- 附录图表必须从正文有明确指引，不能形成无人引用的堆积。
- 图片不铺满整页；按官方版心适度缩小，保留图件原件、配色与构图。
- **本轮用户明确选择**：保留整图并适度缩小；现有 170 mm 图进入 146.4 mm 官方版心时，接受少量最小字约 7.3–8 pt，逐页目检。此例外仅针对既有已制作 P1 图的入版，不把未来出图标准普遍降为 7.3 pt。
- 表格使用 booktabs 粗顶线、细中线、粗底线，无竖线；保留官方 caption 样式。图题在下，表题在上。
- 公式紧接下一段用 `\noindent` 顶格解释内涵和新符号。解释不仅逐字翻译符号，还说明公式如何解决问题。
- 文中须有支撑模型建立或求解的真实命题与证明，以规范的 `\square` 证毕。短证明可在正文；长证明可放附录 B，但正文必须指引。不要用无关定理填充篇幅，也不能把理论性质冒称为估计模型的经验保证。

## 4. 附录分工

- Appendix A — Supporting Materials：支撑材料目录。当前只建目录表框架，不编造已有交付包。
- Appendix B — Supplementary Tables and Figures：补充图表、诊断证据；必要的长证明也可放此处。本轮填写 P1。
- Appendix C — Core Source Code：按 Problem 1/2/3 分组，最终收录核心可运行源代码及软件说明。本轮只建框架，不贴代码。

## 5. 面向评审的英文叙事

- 全文采用自然、准确、简洁的英文，按最终模型逻辑写，不按开发时间线写。
- 不出现内部迭代、版本修补、返工、交接、对话、提示词或工具操作过程；不使用泛化的 AI 宣传和模板化套话。
- 保留必要的模型名、求解器名和统计术语，首次解释。实际验证集用途、阈值、比较范围、条件区间和未验证结论必须交代，不能以删迭代叙述为由隐去方法学边界。
- 结果不逐格播报；先说发现，再给必要数字与比较，再解释含义。
- **首稿验收补充**：禁止连续大段说明堆积。学习数维杯 P1 的实际页面：必要的小标题承担层次，短段交代动机，核心公式承担模型，图表承担证据，短判断说明结论。分点用于真正并列的处理规则、求解步骤和验证结论；不要把所有长段机械改成列表。
- **三线表验收补充**：除了粗—细—粗三条横线，还须检查列宽和表注。纯数值表优先自然宽度居中，避免首列无意义撑满版心、数字全挤一侧；长文字列才用弹性宽度。表注在表宽范围内左对齐并简短，不继承表格居中命令形成整段居中说明。官方 caption 字体/样式保持不变。
- 本轮只列 P1 实际引用的少量文献。按正文顺序编号、正文规范引用；原始文献核验后写入，不堆砌文献。AI 条目最后统一处理。

## 6. 数据与验收

- 既有模型、数据、结果表、拟合账本和图件原件只读。撰稿不触发新拟合、重选模型或新求解。
- 每个关键数字建立内部来源映射；内部路径、哈希与操作日志保留在审计文档，不作为论文叙事。
- 编译后逐页检查官方形式、图文距离、字体、引用、公式说明和数字口径；无中文、身份泄漏、乱码、未定义引用或内容溢出。
- 更新交接，明确已写内容及仍留空部分；当前草稿不冒称最终提交件。

- 目录、正文交叉引用和附录条目须可点击；链接无彩色字或边框，不改变官方外观。重置附录编号时分配独立锚点，逐项核验跳转位置。

- 方法流程图采用紧凑的横向少节点结构，节点只放步骤名及必要求解器/指标。用户已否决复杂的大型嵌套图；折数、参数、数据分工由邻近正文和附录解释，不塞入图中。保留英文、Times New Roman、最终字号至少 8 pt、300 dpi/矢量及灰度可读要求。
