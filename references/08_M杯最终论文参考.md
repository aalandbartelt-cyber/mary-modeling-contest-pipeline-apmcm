## 8.3 可直接迁移的做法

### ① 每问都有“检验与结果讨论”

不是“结果 → 下一问”，而是：

```text
模型/求解 → 结果 → 可行性/一致性 → 参数/消融/负对照 → 边界 → 小结
```

APMCM 每问也应至少有：

- 1 张检验表（检验项/结果/口径/是否支持）；
- 1 张检验图（最多 2×2）；
- 1 个负对照/敏感性；
- 1 条“不能声称”的边界。

### ② 数据/接口只定义一次

论文在 Q1 定义数据契约、缺失处理、0—6 相对等级，Q2/Q3 只引用接口，不重复推导。APMCM 也一样：

- Introduction/Data 里定义数据来源、清洗、单位、缺失；
- 每问只写“本问新增的变量/假设/模型”；
- 共享的预处理/评价指标不要每问重写。

### ③ 技术路线用“共享接口 + 平行分支”

M 杯图1是“数据底座 → 三问分支 → 统一检验”，不是纵向流水线。APMCM 的技术路线图也应这样画：

```text
Data / Problem
  ├─ Question 1: input → model → result → validation
  ├─ Question 2: ...
  └─ Question 3/4: ...
        ↓
  Model Evaluation / Boundaries
```

### ④ 附录 A—E 的分工

- A：支撑材料文件列表（与 ZIP 双向一致）；
- B：补充图表（正文放不下的诊断）；
- C/D/E：每问核心程序（软件名、命令、全部源码）。

APMCM 官方也要求附录有软件名 + 全部源代码，可直接借用这个结构。

### ⑤ 边界句写法

M 杯里大量使用：

- “该区间只反映重复波动，不是新样本预测区间”；
- “影子字段仍有入选，不能写成零误选”；
- “遮蔽对象是折内条件效应前三字段，不是正式 Top-3”；
- “生成谱是统计画像，不是可酿造/安全认证”。

APMCM 的 Model Evaluation/Limitations 应学这种“具体边界”，不要写“模型还有不足”这种空话。
