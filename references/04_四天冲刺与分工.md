# 04 四天冲刺与分工

> APMCM 2026：11/26 06:00—11/30 09:00（北京时间），约 4 天。
> 目标不是“做完所有小问”，而是“在 25 页内交出一条完整、可验证、英文可读的证据链”。

---

## 4.1 时间块

| 时间 | 任务 | 产出 |
|---|---|---|
| D1 06:00—09:00 | 读 A—D，填选题矩阵，定题 | `选题结论.md`、`赛事参数.md` |
| D1 09:00—12:00 | 拆题、数据/假设/符号、模型路线 | `模型路线.md`、`符号表.md` |
| D1 13:00—18:00 | 数据管线/基线；C 题必须完成清洗 | 数据表、基线结果 |
| D1 19:00—23:00 | 第一版 summary 骨架 + 第一张图 | `summary_draft.md` |
| D2 全天 | 主模型求解、第一轮验证 | 结果 CSV、验证表 |
| D3 上午 | 敏感性/对照/补充实验 | 表、图 |
| D3 下午—晚 | 正文英文 v1；summary v2 | 正文 v1/v2 |
| D4 上午 | 英文润色、页数/页眉/目录/编号 | 正文 v3 |
| D4 12:00—18:00 | 最终 PDF、control sheet、支撑包 | 提交件 |
| D4 18:00—21:00 | 只做 P0 检查，不再改模型 | `提交清单.md` |

**硬规则**：

- Summary 从 D1 开始，不是 D4 晚上。
- D3 晚必须有一版完整英文正文；否则 D4 只会烂尾。
- D4 最后 3 小时只做格式/提交检查。

---

## 4.2 三人分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| Modeler | 选题、假设、模型、结果解释、验证设计 | 不包办全部英文写作 |
| Coder | 数据管线、求解、图、复现、包 | 不改模型主张 |
| Writer | 英文正文、summary、格式、提交 | 不编造结果 |

**交叉检查**：

- Coder 给 Modeler 结果 CSV；Writer 只从 `key_numbers.csv` 取数。
- 每天中午/晚上两次 15 分钟对齐：结果、页数、摘要、第二天计划。
- 任何数字不一致，先停下来对 `key_numbers.csv`。

---

## 4.3 每日检查点

### D1 晚

- [ ] 题目已定，题号写进文件名/参数；
- [ ] 数据可用，缺失/单位/口径有记录；
- [ ] 模型路线 1 页；
- [ ] summary 骨架有背景 + 每问 1 句方法；
- [ ] 第一张图/表已有雏形。

### D2 晚

- [ ] 主模型能跑出结果；
- [ ] 结果 CSV 落盘；
- [ ] 至少 1 个 baseline/对照；
- [ ] 第一轮验证表；
- [ ] 正文方法节可写。

### D3 晚

- [ ] 敏感性/负对照至少 1 组；
- [ ] 图表基本齐全；
- [ ] 英文正文 v1 完整（哪怕粗糙）；
- [ ] summary 每问有数字；
- [ ] 页数估算 ≤25。

### D4 中午

- [ ] 正文 v3；页眉/目录/编号正确；
- [ ] 中文扫描 0；
- [ ] 参考文献/附录代码；
- [ ] control sheet 签名；
- [ ] 支撑包/命名。

---

## 4.4 取舍原则

1. 先保证“每问都有回答”，再追求“每问都深”。
2. 若时间不够，砍补充实验，不砍验证/边界。
3. 若页数超，先压背景/重复方法，不删结果/验证。
4. 若英文写不完，先写 summary + 每问结果段，再补方法细节。
5. 不要为了“看起来高级”加没跑过的模型。

---

## 4.5 交付节奏

```text
D1: 选题/数据/路线/summary 骨架
D2: 主结果/验证
D3: 补充实验/图表/正文 v1
D4: 英文润色/格式/提交
```

每天结束前 commit + 归档；不要把 4 天的文件留到最后一次整理。
