# 15 附录、支撑材料与复现（APMCM 版）

> 用途：APMCM 论文附录、可选支撑包、代码/数据/运行说明的交付检查。
> APMCM 的支撑材料是**可选**，但论文附录仍须有软件名 + 全部源代码；不要用支撑包替代附录代码。

---

## 15.1 先分清三个东西

| 东西 | 作用 | 是否必需 | 注意 |
|---|---|---|---|
| 论文附录 | 软件说明 + 全部源代码 + 补充表图 | 按 APMCM 规则 | 代码要能读/能跑；不能只放截图 |
| 支撑材料 ZIP/RAR | 程序、非原始数据、结果、视频等额外副本 | **仅题面明确要求时** | 官方括注：未明确要求请勿提交；命名 `#***fj.rar/.zip`；≤20 MB；不含原始数据 |
| 运行说明 | 环境、命令、输入、输出、未测范围 | 附录/README | 让评委/复现者能照做 |

不要把 control sheet 放进论文或支撑包；它是单独上传文件。

---

## 15.2 附录代码

- 保留完整可执行代码，不是伪代码/截图/片段。
- 删除：工具署名、日期、内部迭代/修补过程、与算法无关的长篇说明。
- 保留：函数/算法注释、输入输出说明、必要依赖。
- 代码文件与支撑包同名源码逐字节一致；不要一个版本在附录、另一个版本在 ZIP。
- 代码路径/文件名与运行说明一致；不要写本机绝对路径/用户名。
- 代码页可读：行号、字体、换行；不要把代码压成不可读的小字。

---

## 15.3 支撑包结构（建议）

```text
<题号><队号>fj/
  01_Source_Code/            可运行源码
  02_Data_Not_Provided/      非原始数据/派生数据/图稿
  03_Results/                结果表/日志/关键输出
  04_Paper_Figures/          论文图源（可选）
  05_Simulation_Videos/      视频（如有）
  06_Software_and_Run_Instructions/  环境/命令/说明
  README.txt                 包结构/入口/依赖
```

- 只放与论文结果对应版本的文件；不要混旧版本。
- 不包含赛题原始数据（除非当届规则明确允许）。
- 不包含姓名/学校/教师/邮箱/本机用户名。
- 压缩包测试能打开；文件名/路径英文；总大小按 APMCM 建议控制。
- 附件清单与 ZIP 实物双向一致；文件数/大小/哈希写进提交记录。

---

## 15.4 运行说明最小字段

```text
Software/language/version:
Dependencies:
Input data (path/env var):
Run command:
Expected outputs:
Runtime (tested):
Random seed/partition:
What was run / what was not run:
Known limitations:
```

- 依赖写版本；不要只写 `pip install -r requirements.txt` 而不给文件。
- 输入数据路径用环境变量/相对路径；不要写作者本机绝对路径。
- 运行命令从干净目录可执行；至少跑通代表性流程。
- 不能复现的部分如实写“未运行/未验证”，不要声称已复现。
- 如果使用官方数据包，写清获取方式/版本；不把原始数据打进包。

---

## 15.5 复现记录

建议保存：

- 运行环境（OS/Python/R/库版本/GPU/CPU）；
- 随机种子/划分文件；
- 输入数据版本/hash；
- 命令与日志；
- 输出文件与论文表/图对应关系；
- 失败/超时/未完成记录。

复现检查不是“能打开文件”；至少证明：

1. 入口脚本能启动；
2. 关键结果能从输入重新生成；
3. 论文数字/图与输出一致；
4. 未复现部分有明确说明。

**便携复现（实战做法）：**

- 把支撑包拷到干净目录，按 README 命令对官方数据包重跑代表性流程，逐行对账结果文件；
- 关键行（区间、得分、覆盖率等）用一段**独立重实现**（如纯 NumPy 按公式重算）逐行比对，容差只许数值噪声；
- 删除文件头说明/注释后，校验可执行 AST 与原版一致——证明清理没改计算；
- 附录与支撑包同名源码逐字节一致；附件清单的文件数/大小/哈希写进提交记录。

---

## 15.6 APMCM 与另一赛事的差异

- APMCM 正文 ≤25 页，附录不限；不要把另一赛事的“附录页数阶梯扣分”套过来。
- APMCM 2026 官方括注“题面未明确要求请勿提交支撑材料”，但代码仍须进论文附录；另一赛事可能把整份附录外置，不能直接照搬。
- APMCM control sheet 单独提交；不要放进论文/支撑包。
- APMCM 对 AI 报告/阈值没有与另一赛事相同的官方模板；按当届 APMCM 规则执行（见 `12_AI工具与学术诚信.md`）。

---

## 15.7 提交前检查

- [ ] 附录有软件名、版本、运行命令、全部源代码；
- [ ] 代码与支撑包逐字节一致；
- [ ] 支撑包命名/大小/结构正确；
- [ ] 不含原始数据/身份信息/密钥；
- [ ] README/运行说明能让别人从干净目录跑；
- [ ] 论文表/图与结果文件同版；
- [ ] ZIP 能打开、无损坏、路径无中文；
- [ ] control sheet 单独提交，未混入论文/支撑包；
- [ ] 未复现部分如实说明。
