# 09 写作与审稿项目规范（APMCM 版）

> 用途：把比赛期间用户反馈、评审意见和返修经验固化成可复用的写作/审稿规范。
> 这是**项目级诊断规范**，不是 APMCM 官方评分表；当届官方规则、模板和评审说明优先。
> 快速结构见 `02_英文论文结构与写作.md`；本文件负责“写出来之后怎么审、怎么改”。

---

## 9.1 先锁定 APMCM 的装订层

写作前先确认，不要把其他赛事的版式直接套过来：

- **首页 Summary，第二页 Contents**；正文从 Contents 之后开始。
- **正文 ≤25 页，附录不限**；2026 官方规范已明确：Summary/Contents 是前置页，不占 25 页；正文从目录后重新从 p1 计。
- 页眉只含队号+页码：官方模板 p1/p2 只有 `Team # <队号>`，正文起左队号 + 右 `Page x of y`（`LastPage`，含附录）；不出现姓名、学校、指导教师、邮箱。
- Control Sheet 单独签名提交，**不进论文 PDF**。
- 正文、图题、表题、图例、坐标轴、附录说明全英文；不允许中文截图。
- 字号按 APMCM 模板（一般 11 或 12 pt）；不要为了压页数擅自缩正文。

**先过装订层，再谈文采。** 页数、页眉、目录、身份和英文泄漏属于 P0；语言润色不能抵消这些错误。

---

## 9.2 Summary：第一页就要形成闭环

APMCM 的 summary 是评委的第一入口。目标 **360—440 词、平均句长 ≤24 词、每问 5—9 个关键数字**，但这不是官方硬门槛；以实际一页排版和信息完整为准。

**结构范式（按题型二选一，详见 `22_数维杯与亚太杯摘要深度解剖.md`）**：
- **证据链型**（算法/预测/调度/工程题）：总领信息纪律 → 每问 [命名模型 → 核心指标 vs 基线/区间 → 负结果或边界] → 收束段列验证体系；
- **品牌分组叙事型**（经济/政策/产业题）：总领命名框架 → Micro/Macro 分组标题 → 每问 [命名发现词 + 模型 + 临界数字/反直觉结论] → Synthesis 收束。

### 每问至少写清四类内容

1. **问题/输出**：这一问要回答什么、输出什么量；
2. **模型归类与思路**：预测/优化/评价/仿真/分类，核心结构是什么；
3. **求解/决策方法**：怎么算、怎么选、关键约束怎么处理；
4. **主要结果与边界**：至少一个数值/比较，说明适用条件和不能声称什么。

### 推荐结构

```text
[1—2 句：现实问题与三项任务/决策]
[1 段：总体框架、数据、验证方式]

For Problem 1, we [method]. [Key result with value and baseline.]
For Problem 2, we [method]. [Key result with value and condition.]
For Problem 3, we [method]. [Key result with value and tradeoff.]

[1—2 句：结论、限制、未声称的内容]
Keywords: ...
```

### 常见扣分

- 只写“建立了模型/进行了分析”，没有结果数字；
- 每问数字与正文/结果 CSV 不一致；
- 把“首先/然后/接着”的流程记录当摘要；
- 只报最好的结果，不写代价、失败场景或评估身份；
- Summary 跨页，或把 Contents 挤到第 1 页；
- 摘要里塞公式、图、表、参考文献角标。

### 摘要审稿顺序

1. 遮住正文，只读摘要：能否复述三/四问的方法+结果+边界？
2. 逐项对账：`指标 | 单位 | 数据/场景 | 比较基准 | 数值/分母 | 正文位置`。
3. 检查时态：已完成的操作过去时；定义/一般关系现在时；结论按语境。
4. 检查英文：长句、冠词、单复数、术语漂移、全角标点。
5. 最后才做“高级表达”；不要用润色掩盖数字或逻辑问题。

## 9.3 正文：把得分点放在明处

每一问按以下顺序组织，标题可按题目调整：

```text
Problem analysis → Assumptions/notation → Model → Solution/algorithm
→ Results → Validation/sensitivity → Direct answer → Boundary
```

### 每节开头先给判断句

评委是翻着找得分点，不会逐字读。每节前 1—2 句先回答“这一节解决什么/得到什么”，再展开过程。

### 直接回答小节

每问结尾加一个短小节，例如 `Direct answer to Problem 2`，用 3—6 句回答题目原话：

- 预测/决策是什么；
- 关键数值/条件；
- 与基线相比如何；
- 哪些结论成立、哪些不成立。

这比在长段落里埋结论更容易得分。

### 前置压缩与附录分流

- **前置 ≤ 3–4 页（≤16% 篇幅）**：Intro + Problem Analysis + Assumptions + Notation 压进正文前 3–4 页（第 2 页放整页图文混排技术路线图），把 80%+ 正文留给建模、实证、敏感性与评价（见 `21_自有论文蒸馏.md` §21.11）。
- **命题与证明进附录 B**：正文写一句结论+指针（`Appendix Proposition N`），完整命名命题 + 6–15 行紧凑证明 + `□` + 适用边界尾句放附录 B，既显数学深度又不拖慢正文节奏。

### 问题重述不要抄题

- 用 2—4 句写背景/对象/为什么重要；
- 用“本题要求/需要解决”列出子问题，保留关键条件、单位、约束；
- 至少写 1 个题面歧义/隐藏条件及处理方式；
- 不要大段复制题面；抄题会提高相似比，也会让评委觉得没有理解。

### 假设与符号

每条关键假设尽量写清：

```text
依据（题目/数据/机理/文献） + 适用范围 + 失效后的影响
```

符号表只做汇总；符号首次进入正文时仍要解释含义、索引、单位、维度、取值范围。跨问复用符号时避免含义冲突。

### 模型选择动机

不要只写“本文采用 XX 模型”。至少写：

```text
问题结构 → 候选方法 → 选择理由 → 代价/边界 → 基线/对照
```

方法复杂不等于模型好；能回答题目、可验证、可复现才是核心。

## 9.4 结果叙事：先结论，再数字，再解释

推荐句式：

```text
[结论句] Table 4 shows that [method] gives [value], compared with [baseline] ([value]).
[含义句] This [absolute/relative] difference means [interpretation].
[边界句] The result holds for [scope]; it does not establish [out-of-scope claim].
```

要点：

- 区分绝对差、相对百分比、百分点；不要混用。
- 说明分母、样本量、数据划分和评价单位。
- 关键数字给 3—4 位有效数字；一串六位小数是日志不是结论。
- 每个结果小节首句写结论（“这说明什么”），不只陈列数字。
- 边界句必须落到可核查身份——哪个数据集、哪次评估、什么条件；不写“证据有限”“仅作参考”这类说不清身份的空话。
- 不只报有利结果；关键约束恶化、失败案例、覆盖率不足要写。
- 结论要敢下：评委欣赏基于模型的明确政策/方案判断，骑墙和稀泥扣分；判断超出证据就降级措辞，而不是模糊掉。
- 图表只放关键结果；正文解释“看到什么/意味着什么”，不要逐格播报。
- 相关不自动等于因果；候选集内最优不等于全局最优。
- 训练拟合、验证选模、未参与选择的测试、已打开记录复评要分开命名。

详细口径见 `11_验证与结果叙事.md`。

## 9.5 英文表达与术语

- 一句一个主张；50+ 词长句拆成 2—3 句。
- 方法/实验用过去时；定义/一般关系用现在时；结论按语境。
- 术语首次出现给全称/定义；同一概念只用一个英文词。
- 数字+单位；百分比写 `%`；千分位、日期、货币口径全文一致。
- 不用 `very significant / obvious / best` 这类无证据评价；给数值和比较。
- 全文搜中文和全角标点：`，。；：（）【】“”`；图内中文必须重绘。
- 中文草稿转英文时，先对齐题意、术语、公式、数值和证据，再润色；不要在翻译中加强结论。

## 9.6 排版与篇幅

- 正文 ≤25 页；优先压缩重复叙述、教科书式算法介绍、与得分点无关的背景。
- 普通结果页不要出现“整页只有图”或大段留白；图与解释相邻，必要时用局部换页。
- 核心结果表/图优先放正文；完整表、补充图、过程日志放附录。
- 页数出现余量时，优先把附录中的核心结果表回正文（误差、覆盖、关键比较），而不是加背景或凑内容；详细格阵仍留附录。
- 同一量跨问复用时口径必须一致；口径不同的要一句话解释差异（如 Q1 半径 0.53 与 Q2 半径 1.25 相差 2.3 倍需说明原因）。建 `terminology.md` 登记量名、定义、单位、首次出现位置。
- 正文 11/12 pt；图内最终印刷字号目标 ≥8 pt，至少不低于 7 pt；不要靠缩字号压页。
- 表不跨页；跨页表重复表头；图题在图下，表题在表上。
- 参考文献按引用顺序；每条都在正文出现；不编造、不写僵尸文献。
- 附录代码保留完整可执行代码；删除工具署名、日期、内部迭代/修补过程文字，保留正常算法注释。

图表和排版的详细检查见 `10_图表与排版项目规范.md`。

## 9.7 审稿输出格式

每次自审/互审按以下格式落盘，避免“感觉还行”：

```markdown
# APMCM Paper Review
- Paper/version/pages/body pages:
- P0（不修不能交）:
- P1（影响得分）:
- P2（打磨）:
- Number check: summary ↔ body ↔ table/figure ↔ CSV
- Coverage: checked / not checked
- Verdict: submit / revise / block
```

每条问题写清：位置、观察/数据、对结论或交付的影响、修复动作、复验条件。不要用“加强模型/提高美观”这类空话。

---

## 9.8 停止条件

1. 正文 >25 页且只能靠删关键结果压缩 → 先重写重复叙述，不要删证据。
2. Summary 与正文数字不一致 → 先回源 `key_numbers.csv`，不要继续润色。
3. 只剩语言润色且时间 <3 h → 停止改模型，只做格式/提交检查。
4. 题号/队号/文件名/页眉不确定 → 停下来查当届官方，不要猜。
